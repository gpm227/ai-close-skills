# Build a brand system from a deck and a website

Give a second writer and designer enough to produce a recognizable piece without the original conversation. ChatGPT owns intake, source decisions, the editable guide, the copy and the review record. Use Claude Design or the partner's chosen design tool for visual production.

## Start with the materials

For an explicit demo, read [the fictional repair-shop request](examples/brief.md), then run `python3 scripts/render.py examples/example.json demo-output` from the skill folder. For a real brand, use the client's files. Never substitute the demo for an inaccessible input. The partner supplies business materials and receives usable files. The agent handles JSON and commands. If code execution is unavailable, deliver editable Markdown and label which renders are outstanding.

1. Read the deck as rendered slides as well as text. Open the supplied website or use labeled page captures. Inspect the relevant service or audience page and the destination of the proposed action. Record what can actually be established about that destination. A snapshot can establish the displayed destination and form wording; a successful submission requires separate evidence.
2. Map each distinctive decision to a locator (slide number, exact URL and section, or capture filename and section) and a short exact excerpt or a labeled visual observation. Record cover, body, and CTA treatments at presentation and thumbnail sizes. Distinguish verified CSS or supplied font files from a screenshot estimate. Never identify an exact font or hex value by appearance alone.
3. Record which inputs were inspected, captured offline, or unavailable. With one usable source, produce a provisional guide from it and identify which decisions would change with the missing input. With zero usable sources, request one file, capture or export and pause the reconstruction. Never invent a second source.
4. Label each source public, internal, or unconfirmed. Record competing versions and what would change for a buyer. Use an explicit owner's instruction or a clearly authoritative, current source to resolve the difference. An observed live form establishes its actual next step. An internal slide cannot enlarge a public claim. Hold a disputed claim, logo, or commitment until the specific owner decision is documented. If nothing has clearance for publication, deliver the private guide and voice brief with `sheet: null`; keep buyer copy and production pending.

## Freeze the job

Write a short, dated spec with the selected audience, job, actual action after the CTA, files, destination/format, and the owner's examples. Keep observable criteria for **V1 voice fidelity**, **V2 distinct visual jobs**, and **V3 low text density**. Specify what to inspect for this company. Preserve the original across both design reviews. A new owner decision creates a new benchmark version. Preserve the old verdict and the rejected comp. Capture the specific treatment that failed, the implied buyer need, and one observable criterion for the new version. The latest authorized decision governs the next comp.

**Design distinctiveness.** Bring one visual source from the company's actual work: a marked-up form, on-site detail, tool reading, annotated photo, sample output, or a buyer's real decision record. In the first scan, the visual should teach a buyer something the headings alone cannot communicate. Name that fact, its source and the mark, feature or relationship a reviewer can point to. Where a useful asset is missing, ask for the one specific capture that changes the design. Return a transcript or labeled wireframe meanwhile. Sparse evidence cannot establish a house typeface, canvas treatment, or image style.

For each color and type role, distinguish an exact source value and its scope, a production choice and its reason, or an unknown. A typeface in one receipt, or the substrate of a photographed form, does not become a company-wide brand rule. Use a supplied design reference to identify a functional principle: for example, a service-specific action should carry the selected service into the enquiry. Apply that idea to this company's buyer, material and actual action; leave the other company's type, palette, copy and art behind.

When an owner supplies a strong finished piece, inspect it at full and thumbnail sizes. Record its focal point, answers to buyer questions, reading order and where images convey information. Note the design principles that transfer to this audience. Identify reference-specific copy or pending assets that must stay out of the new piece.

## Derive rules and apply them

- **Voice.** Name the buyer, the product mechanism and who takes each action. For each material rule use a source cue, an instruction, and an original before/after rewrite. Preserve qualifications. Distinguish observed terminology from proposed editorial treatments. Try one fresh headline or follow-up in a different channel. If a competitor could use it unchanged, make the rule more specific.
- **Visual identity.** Separate observed rules from proposed extensions. Assign colors to text, background and action. Specify headline/body hierarchy, available fonts and channel fallbacks, logo proportions, icon geometry, spacing and density. A missing logo gets a labeled wordmark placeholder. An unspecified typeface stays unspecified. Set the minimum production fallback required to read the proof and label it accordingly. Avoid treating a familiar serif, tinted background, grid/callout, or any other favorite treatment as an identity. Verify rights for artwork. No unsupported font or logo files go in the handoff.
- **Composition.** Identify the relationship the buyer needs to see: an ordered handoff, parallel services, a comparison, or a choice supported by proof. Name the focal point, order, geometry or photography, distinct icon meanings, and what a buyer should understand at first scan. Add a supporting line only when it adds a decision, actor, qualifier or fact. A word limit applies only when supplied by the owner or format.
- **Claims.** Trace the headline, supporting claims and proposed action to cleared sources. Verify their actual meaning, including geography, deadlines, conditions and permissions. A syntactically valid reference or URL cannot confirm a promise. Explicitly mark a missing destination as unresolved and keep the draft out of circulation.

## Build the handoff

Read [the editable file format](references/format.md). Populate `brand.json` and run `python3 scripts/render.py brand.json OUTPUT_DIRECTORY` using a new directory. Keep the editable brand JSON and source-register guide (`guide.html`) with the authorized owner. For a partner handoff use `partner-guide.md`, an editable Markdown guide with the shareable writing examples and visual rules. Include the portable voice brief, design brief and HTML copy proof. Check all selected token values, production notes and assets for the intended recipient. A guide-only job returns two explicitly internal files and generates no partner guide. Check the guide against the source register, then open the actual proof at the target size. Inspect typography, clipping, action contrast and readability of any printed destination. File creation alone cannot prove a visual pass.

For Claude Design, give the designer the handoff, the intended delivery size, the approved logo or substitute, and only the assets the partner authorized for that tool. The designer should receive the exact tokens, type fallbacks, icon assignments, copy, next action, and an observable composition test. Request an editable design plus a rendered export. When production access or authorization is missing, deliver those files to the partner and mark the comp pending. Keep private source excerpts and owner references in the approved workspace.

## Review two actual versions

**Cross-brand substitution test.** On the rendered design temporarily cover the logo, company name, and category headline. Ask a fresh reviewer to name the job and point to the visual evidence that identifies it. Then substitute a plausible unrelated company with the same generic promise and ask which part of the composition would need redrawing. An unchanged image/card grid with swapped nouns fails. Record the actual region, the expected buyer inference and the reviewer's answer. A genuine shared industry convention can stay; the job-specific device must still convey a meaningful decision. An owner's rejection is a failed taste check even if all technical checks pass.

Preserve the first design export. In a separate reviewer turn compare its focal point, buyer promise, reading order and visual explanation to each frozen criterion. Record version or checksum, pass/fail/unknown, the exact copy or page location, and the edit. Render the revision. In a second reviewer turn inspect that new export at delivery size against the same criteria. Check what remains clear without explanatory paragraphs, read the copy aloud, verify qualifications and follow the next action as far as authorized. Apply any further correction and inspect the resulting change. Keep improvements that survived both reviews.

In a single-turn environment deliver the current stage and continue from the preserved export in subsequent turns. A copy proof can establish copy and layout checks, never a finished design review. Keep unknown criteria visible. The owner determines when the design becomes their template. Report the actual files, completed checks and the smallest decision that still blocks use.
