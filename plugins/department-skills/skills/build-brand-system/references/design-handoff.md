# Scope and review an applied piece

Write a short, dated spec with the selected audience, job, actual action after the CTA, files, destination/format, and the owner's examples. Keep observable criteria for **V1 voice fidelity**, **V2 distinct visual jobs**, and **V3 low text density**. Specify what to inspect for this company. Preserve the original across both design reviews. A new owner decision creates a new benchmark version. Preserve the old verdict and the rejected comp. Capture the specific treatment that failed, the implied buyer need, and one observable criterion for the new version. The latest authorized decision governs the next comp.

**Design distinctiveness.** Bring one visual source from the company's actual work: a marked-up form, on-site detail, tool reading, annotated photo, sample output, or a buyer's real decision record. In the first scan, the visual should teach a buyer something the headings alone cannot communicate. Name that fact, its source and the mark, feature or relationship a reviewer can point to. Where a useful asset is missing, ask for the one specific capture that changes the design. Return a transcript or labeled wireframe meanwhile. Sparse evidence cannot establish a house typeface, canvas treatment, or image style.

For each color and type role, distinguish an exact source value and its scope, a production choice and its reason, or an unknown. A typeface in one receipt, or the substrate of a photographed form, does not become a company-wide brand rule. Use a supplied design reference to identify a functional principle: for example, a service-specific action should carry the selected service into the enquiry. Apply that idea to this company's buyer, material and actual action; leave the other company's type, palette, copy and art behind.

When an owner supplies a strong finished piece, inspect it at full and thumbnail sizes. Record its focal point, answers to buyer questions, reading order and where images convey information. Note the design principles that transfer to this audience. Identify reference-specific copy or pending assets that must stay out of the new piece.

## Package a requested design handoff

Read the [editable file format](format.md). Populate `brand.json` and run `python3 scripts/render.py brand.json OUTPUT_DIRECTORY` using a new directory. Keep the editable brand JSON and source-register guide (`guide.html`) with the authorized owner. For a partner handoff use `partner-guide.md`, an editable Markdown guide with the shareable writing examples and visual rules. Include the portable voice brief, design brief and HTML copy proof. Check all selected token values, production notes and assets for the intended recipient. In the renderer, `sheet: null` creates an internal register and voice brief. For a guide-only partner request use the editable guide workflow above. Check the guide against the source register, then open the actual proof at the target size. Inspect typography, clipping, action contrast and readability of any printed destination. File creation alone cannot prove a visual pass.

For Claude Design, give the designer the handoff, the intended delivery size, the approved logo or substitute, and only the assets the partner authorized for that tool. The designer should receive the exact tokens, type fallbacks, icon assignments, copy, next action, and an observable composition test. Request an editable design plus a rendered export. When production access or authorization is missing, deliver those files to the partner and mark the comp pending. Keep private source excerpts and owner references in the approved workspace.

## Review versions of a commissioned design

**Cross-brand substitution test.** On the rendered design temporarily cover the logo, company name, and category headline. Ask a fresh reviewer to name the job and point to the visual evidence that identifies it. Then substitute a plausible unrelated company with the same generic promise and ask which part of the composition would need redrawing. An unchanged image/card grid with swapped nouns fails. Record the actual region, the expected buyer inference and the reviewer's answer. A genuine shared industry convention can stay; the job-specific device must still convey a meaningful decision. An owner's rejection is a failed taste check even if all technical checks pass.

Preserve the first design export. In a separate reviewer turn compare its focal point, buyer promise, reading order and visual explanation to each frozen criterion. Record version or checksum, pass/fail/unknown, the exact copy or page location, and the edit. Render the revision. In a second reviewer turn inspect that new export at delivery size against the same criteria. Check what remains clear without explanatory paragraphs, read the copy aloud, verify qualifications and follow the next action as far as authorized. Apply any further correction and inspect the resulting change. Keep improvements that survived both reviews.

In a single-turn environment deliver the current stage and continue from the preserved export in subsequent turns. A copy proof can establish copy and layout checks, never a finished design review. Keep unknown criteria visible. The owner determines when the design becomes their template. Report the actual files, completed checks and the smallest decision that still blocks use.
