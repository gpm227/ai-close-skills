# Reproduce the library trials

Three fresh workers each received twelve independent fictional requests. The workers used the matching skill without the reviewer's answer key. The reviewer checked the actual outputs against criteria fixed before the run. The separate brand-system trial used a fictional deck and a captured site. All material in this directory is synthetic.

**Deployment guide.** An independent maintainer followed the instructions in a clean checkout. The installer made 37 private ZIPs. The maintainer tested release updates and rollback, capture and retry, and the two reporting examples. A new private September export yielded 80 → 100 orders (+25%). An extra field claiming orders fell 40% correctly caused the checker to fail. Every public ZIP includes a catalog and deployment link; every private ZIP carries a release receipt and the path to its company guide. Nine of ten guide acceptance checks have local evidence. Verification with two employees in a live workspace remains open.

The original account qualification produced a correct eligible list from incorrect evidence. It turned aggregate counts into fictitious site records. The repaired skill preserves the scope of the published count and leaves individual sites unverified. The original outbound experiment proposed a sound assigned-account measure but omitted the delivered-account comparison. Its revision preserves both denominators. The archive includes first attempts and corrected outputs.

For a fresh run, select one request and supply only its inputs and the matching ZIP. Save what the worker produces. Then open the answer key, inspect actual artifacts and note missing evidence. The archive has readable examples of target lists, sales copy, a four-slide deck with speaker notes and a printable one-sheet. These checks establish performance on one unseen case per job. Native workspace installation, owner judgment, business outcomes and performance on new jobs need their own evidence.

To replay the brand comparison, run the installed brand renderer with `brand-handoff/worker-source.json` as input and an empty destination. Inspect the private and partner files separately. The public design example and its visual review are distinct from this source-fidelity test.
